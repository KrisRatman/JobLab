# Бэкенд JobLab

Платформа построена на штатных сущностях WordPress, поэтому модерация работает
в обычной консоли без отдельной админки.

## Структура данных

| Сущность    | Где живёт                              | Комментарий |
|-------------|----------------------------------------|-------------|
| Вакансия    | тип записи `jl_vacancy`                | автор — работодатель |
| Компания    | тип записи `jl_company`                | одна на работодателя, создаётся вместе с первой вакансией |
| Отклик      | тип записи `jl_application`            | автор — соискатель, в мете `_jl_vacancy_id`, `_jl_employer_id` |
| Категории   | таксономия `jl_category` (иерархическая) | |
| Навыки      | таксономия `jl_skill` (теги)           | висят и на вакансии, и на работнике |
| Работник    | пользователь с ролью `jl_seeker`       | профиль в usermeta `jl_*` |
| Работодатель| пользователь с ролью `jl_employer`     | |

Навыки работника хранятся отдельными строками usermeta `jl_skill` (по одной на
навык) — по ним идёт подбор кандидатов в `jl_find_candidates()`.

## Страницы

Создаются автоматически при активации темы, их ID лежат в опции `jl_pages`:
`/login/`, `/register/`, `/cabinet/`, `/vacancy-form/`, `/candidates/`, `/blocked/`.
Каталог вакансий — архив типа записи: `/vacancies/`.

## Модерация

* **Вакансия.** Статус `jl_banned`. Из публичных выборок выпадает, по прямой
  ссылке отдаёт 404 всем, кроме автора и модератора. Автор видит текст
  «Ваша заявка не удовлетворяет требования платформы».
* **Работник.** Usermeta `jl_banned`. Вход отклоняется, любая страница
  перебрасывает на `/blocked/` с текстом «Вы были заблокированы за
  неудовлетворение требований платформы».
* **Автоочистка.** Ежедневный cron `jl_cleanup_banned` удаляет заблокированное
  старше `JL_BAN_TTL_DAYS` (14 дней) вместе с откликами и компанией. Если cron не
  отрабатывал, чистка догоняется при заходе модератора в консоль.

Кнопки блокировки — в списке вакансий (действия в строке и массовые),
в карточке вакансии и в списке пользователей.

## Одобренные отклики

Когда работодатель ставит отклику статус «Приглашение» (`_jl_state = invited`),
в кабинете соискателя карточка отклика становится зелёной, а жирным шрифтом
написано, где его ждут (`jl_get_invitation()` в `inc/data.php`):

| Поле вакансии `_jl_meeting` | Что видит соискатель |
|-----------------------------|----------------------|
| `office`                    | «Вас ждут на очной встрече в офисе» + адрес офиса компании |
| `call`                      | «Вас ждут на созвоне» + контакт вакансии |
| не указано                  | «Работодатель одобрил ваш отклик» + контакт для уточнения формата |

Формат задаёт работодатель в форме вакансии, адрес офиса — в блоке «Компания»
той же формы (мета компании `_jl_address`). Оба поля правятся и в консоли:
у вакансии — в блоке «Параметры вакансии», у компании — «Адрес офиса».

## Файлы

```
inc/setup.php          типы записей, таксономии, роли, статусы, установка страниц
inc/data.php           профили, вакансии, отклики, подбор кандидатов, фильтры каталога
inc/auth.php           регистрация, вход, перехват заблокированных
inc/forms.php          обработчики форм фронтенда (admin-post.php + nonce)
inc/moderation.php     блокировки в консоли и автоудаление
inc/admin.php          сводка модератора, метабоксы, тестовые данные
inc/template-tags.php  карточки, плашки навыков, уведомления
inc/seed.php           генератор демонстрационных данных
```

Формы отправляются на `admin-post.php`. Учтите: этот файл тоже вызывает
`admin_init`, поэтому редирект обычных пользователей из консоли
(`jl_block_admin_access`) его намеренно пропускает.
